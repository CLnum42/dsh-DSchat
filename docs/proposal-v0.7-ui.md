**2. 两套中性色，冷热混用。**

| 出现位置 | 现在的值 | 温度 |

## 二、提案：一套色

### 2.1 三条规则

1. **一个强调色族**：DeepSeek 蓝。`#4176e6`（浅）/ `#7aaaff`（深）。
   凡是「开启中」「主操作」「当前项」都用它——发送键、亮的开关、焦点环、选中行、
   状态灯、引用角标、新会话页图标块。
2. **一套中性色**：`neutral-bluish` 蓝灰阶（`#fff → #f1f3f5 → #ebeef2 → #e1e5ee`，
   深色 `#151517 → #232324 → #2c2c2e → #353638`）。暖灰 `#f5f5f5` 与冷藏青
   `rgba(38,49,72,…)` 全部退场。蓝灰阶是**静态 token，不随主题翻转**，所以深色
   分支不用再逐个重写（现有 `styles.ts` 里有一堆 `body[data-ds-dark-theme]`
   补丁就是被这个逼出来的）。
3. **四个面，两个主题都有真实台阶**：

| 面 | 用途 | 浅色 | 深色 |
|---|---|---|---|
| page | 页面底 | `#fff` | `#151517` |
| raised | 输入卡片 | `#fff` + 描边 + 轻阴影 | `#232324` + 描边 |
| sunken | 已思考框 / 参考来源 / 附件条 / 引用角标底 | `#f1f3f5` | `#2c2c2e` |
| quiet | 用户气泡 | `#f1f3f5` + 细描边 | `#2c2c2e` |

> 用户气泡**故意和 sunken 同一级**、不加蓝：强调色是留给「状态」的，
> 一个永久发蓝的气泡会是正文区最吵的东西，抢走读者真正要读的回答。

### 2.2 逐项对照（浅色 / 深色）

| 元素 | 现在 | 提案 |
|---|---|---|
| 页面底 | `#fff` / `#151517` | 不变（它是对的） |
| 输入卡片 | `#fff`，只有 10% 黑细线 | `#fff` + **`#e1e5ee` 描边 + 轻阴影** / `#232324` |
| 卡片聚焦 | 描边变 `border-l3`（几乎看不出） | **2px 蓝环**（强调色 52% + 12% 光晕） |
| 输入框占位文字 | `#81858c`（3.71:1） | `#81858c`（**不变**，实测 3.71:1，不允许回退） |
| 搜索框 | 有描边、聚焦变暖灰 `#f5f5f5` | **无描边填 `#f1f3f5`**，聚焦给同一套蓝环 |
| 会话列表选中行 | 冷藏青 10% | **强调色 10%**（和右侧一切「当前项」同一个蓝） |
| 用户气泡 | 冷藏青 6% | `#f1f3f5` + `#e9ecf2` 细描边 / `#2c2c2e` |
| 已思考 / 参考来源 | 浅色 `#fff`（和白页同色） | `#f1f3f5` / `#2c2c2e` |
| 引用角标 `¹` | `#fff` + 灰字 | 强调色 10% 底 + 24% 边 + **`#283142` 字**（≈11:1） |
| 开关（亮） | 三种蓝拼一起 | 强调色 12% 底 + 36% 边 + **`#283142`/`#7aaaff` 字**（9.9:1 / 7.1:1） |
| 发送箭头 | 浅色：近黑 `#0f1115` 画在 `#4176e6` 上 = **4.46:1**；深色：近白画在亮蓝上 = **2.23:1** | 白色（浅）/ 近黑（深）——**箭头随强调色翻转，不随主题名**：浅色 20.9:1，深色 15.6:1 |
| 发送键禁用 | 整键 `opacity:.4`，箭头跟着一起淡掉 | 圆盘**混色变淡**（浅色 60% 强调色、深色 82% 强调色提亮），**箭头不淡** |
| 新会话页图标块 | 近黑（浅色）/ 近白（深色） | **强调色**，两种主题都是 |
| 菜单 / 弹层描边 | 深色用 `border-l3` 补丁 | 统一 `#ffffff1f`，补丁删除 |

深色主题还修了一个实测到的**层叠 bug**：亮开关的深色分支特异性是 (0,3,0)，
新规则 (0,2,0) 会被它压住——所以在候选样式里深色分支显式写足权重，实测底色已从
`#34415b` 变成 `rgba(122,170,255,.12)`。

### 2.3 发送箭头的反差（你的第一条反馈）

箭头原来画的是**近黑**，不是白：面板开头有一条 `.dsh-dschat button { color: inherit }`
（0,1,1），而 `.dsh-dschat-send` 只有 (0,1,0) —— 单类规则**输给了那条兜底规则**，
所以箭头一直是继承来的面板墨色。修法是 `button.dsh-dschat-send`（0,2,1）显式指定，
和当年 `.dsh-dschat-toggle-on` 踩过的坑是同一个（那张表里已经记过一次）。

修完还要**反向**处理深色主题：强调色在浅色下是深蓝 `#4176e6`、在深色下是亮蓝
`#7aaaff`，所以墨色必须跟着强调色走 —— 浅色白箭头、深色近黑箭头。原来的
`label-primary-inverted` 正好反着来：浅色给白（4.46:1）、深色也给近白（2.23:1），
这就是「有点暗淡」。

禁用态也一并改了：原来是整键 `opacity:.4`，箭头跟着淡到和圆盘一个调子。现在
**只把圆盘混淡、箭头保持满强度**（浅色 60% 强调色，深色 82% 强调色提亮）。

## 六、怎么再生成一次对照图

`scripts/proposal-preview.mjs` 还在，它把「现在」和「另一份样式表」并排渲染
（同一份真实组件、同一份 locale，只有样式表不同）。`--candidate` 现在可选，
说明文字也可以从命令行给：

```bash
# A. 配色试验：写一张只覆盖 token 的小表
node scripts/proposal-preview.mjs --out .tmp-proposal --candidate .tmp/candidate.css

# B. before / after：把上一版的 styles.ts 整张当候选表（完整旧表会重述它自己的
#    每一条规则，所以追加进去就能复现旧面板）
node scripts/proposal-preview.mjs --out .tmp-before-after \
  --candidate .tmp-web/old-panel.css \
  --label-left '新配色 · DeepSeek 网页端' --tag-left new \
  --label-right '旧配色 · 上一版' --tag-right old \
  --note '右侧额外加载了上一版的 <code>styles.ts</code>，其余完全相同。'
```

`--out` 的目录里除了四张对照 PNG，还有 `report.json`：每个元素在两个渲染里的
实际底色 / 文字色 / 描边，以及占位文字与开关标签的对比度。想再改一次配色时，
先跑它、看着数值改，比反复截图快得多。

注意 `--candidate` 的路径按仓库根解析；`--tag-*` 只认 `old` / `new` 两个值。

## 七、第二次配色对齐（0.6.4）：直接用网页端的色

### 7.1 为什么又改一次

你反馈「颜色有点太深了，就用 deepseek 网页端的配色」。查下来原因很具体：上一稿
的 `--dschat-accent` 读的是 harness 的 `--dsw-static-deepseek-500/400`，而**同名的
两步在网页端和 harness 里不是同一个色**：

| token | harness | 网页端（chat.deepseek.com） |
| --- | --- | --- |
| `deepseek-500` | `#4176e6` | `#3964fe` |
| `deepseek-400` | `#7aaaff` | `#679efe` |

其余各步（50/100/200/300/450/600/800/900）两边完全一致，中性蓝灰阶、边框 alpha、
交互 wash、三档文字色也完全一致 —— 也就是说**这套设计系统两边是同一套，只有那两个
蓝被 harness 改过**。所以这一稿不是重新配色，是把那两个值换成网页端的。

网页端的取值来源：`https://fe-static.deepseek.com/chat/static/main.*.css` 里的
`body{}` 与 `body[data-ds-dark-theme]{}` 两个 token 块，加上在真实页面上量的元素色。

### 7.2 逐项对照

| 用途 | 0.6.3 | 0.6.4（= 网页端） |
| --- | --- | --- |
| 强调色（浅/深） | `#4176e6` / `#7aaaff` | `#3964fe` / `#5686fe`（网页 `brand-primary`，就是它的发送圆盘） |
