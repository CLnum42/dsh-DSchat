## 2. 顶部 header —— 只留「品牌 + 状态灯」

| 项 | 内容 |
|---|---|
| 高度 | 52px（不变） |
| 左侧 | 🐳 蓝鲸图标 19px + 文字 **DeepSeek Chat** |
| 文字样式 | 13.5px / 500 / `--dsw-alias-label-primary`，单行不换行 |
| 状态灯 | 图标右侧 8px 处一个 **7px 圆点**，可点击 |
| 右侧 | 空（保留拖拽区 `data-window-drag`） |
| 删除 | 三个 header 按钮 `[▤][🔍][＋]`、`在 Harness 中继续` 按钮、`···` 菜单按钮 |

### 2.1 状态灯语义（严格按需求）

| 颜色 | 触发 phase | 含义 | Tooltip |
|---|---|---|---|
| 绿 `--dsw-alias-state-success-primary` | `ready` | 正常运行 | 已就绪 · deepseek-reasoner |
| 黄 `--dsw-alias-state-warn-primary` | `launching` / `need-login` | 启动中 / 未登录 | 正在启动浏览器 / 未登录（**新增档位，见 §6-Q2**） |
| 红 `--dsw-alias-state-error-primary` | `error` | 故障 | 引擎错误：<详情> |
| 灰 `--dsw-alias-state-idle-primary` | `stopped` | 未启动 | 未启动 |
| 绿 + 呼吸 | `thinking` / `streaming` | 正在工作 | 正在思考 / 正在输出 |

> 工作态沿用现有「同色呼吸」做法（不改色、只做 opacity 动画），避免多一个蓝色和 ready 混淆。

### 2.2 状态灯的第二个身份：图形化后的 `···` 菜单

原 header 的 `···` 菜单（运行状态 / 导出 Markdown / 打开登录窗口 / 关闭浏览器）不能就这么消失——它是「运行状态」诊断卡和「打开登录窗口」的唯一入口。

**做法：点击状态灯 = 打开一个与状态灯同色的小面板**，内容：

```
● 已就绪 · deepseek-reasoner        ← 原 whale tooltip 的整句
─────────────────────────────
运行状态            ← 打开诊断弹窗（DSchatStatus）
导出 Markdown
打开登录窗口         ← 仅未登录时显示
关闭浏览器           ← 仅引擎停止时显示
```

- 圆点本身**不再承担"启动引擎"的点击语义**（原来点鲸鱼会 `ensureReady()`）——改为「状态即入口」，更符合直觉；启动仍由输入框聚焦自动触发。
- 无鼠标用户：圆点是 `<button>`，`aria-label` 带完整状态句，`aria-haspopup="menu"`。

## 3. 新增：输入框正上方的动作行 `.dsh-dschat-actions`

位置：**输入卡片之外、消息流之下**，与输入卡片共用左右内边距（对齐到卡片边缘）。

```
[▤] [🔍] [＋]                                    [⇄ DSH迁移 ▾]
└── 左组：会话动作 ──┘                            └── 右组：迁移 ──┘
```

| 元素 | 规格 | 行为（不变的部分照旧） |
|---|---|---|
| `[▤]` 历史 | 30×30，圆角 8px，`--dsw-alias-label-secondary` | `toggleRail()`；开启时 `-on` 态（浅蓝底 + 蓝字）。快捷键不变 |
| `[🔍]` 搜索 | 同上 | `openSearch()`，聚焦 rail 搜索框；`⌘K` 不变 |
| `[＋]` 新对话 | 同上 | `newChat()`；`preparingNewChat` 时 disabled |
| `[⇄ DSH迁移 ▾]` | 高 28px，padding 0 10px，图标 14px + 文案 13px + caret 11px；沿用现有 `dsh-dschat-btn-primary` 视觉（蓝调） | 点开**原封不动**的迁移 popover（模式：蒸馏/原文；目标：新建/追加；工作区；进度 3 步）。**迁移完成后 popover 自动关闭**（新增，原来打开新会话后面板卸载所以不复现，现在按钮常驻必须关） |

**为什么左对齐、迁移右对齐**：左边三个是「看/换会话」，属于浏览动作；迁移是「把这次对话交出去」的终结动作，和发送键一样靠右，符合"左浏览右提交"的既有分组逻辑（工具行的 深度思考/联网 ←→ 附件/发送 同一套逻辑）。

**迁移按钮的可达性**：
- 无会话或会话为空 → disabled（同现状 `viewChat.messages.length === 0`）
- 迁移动画进行中 → disabled + 按钮内联 spinner
- `title` = 「在 Harness 中继续」，`aria-label` = 「DSH 迁移」

## 4. 附件：保留真名 + 图片缩略图

### 4.1 问题根因

- 客户端的 `images` 状态只存**路径字符串**，chip 用 `path.split('/').pop()` 取名；
- 宿主 `/attach` 落盘名是 `${randomUUID()}${ext}`；
- 两者叠加 → 界面显示 `3f9c1e2b-....png`。

### 4.2 方案：路径前缀带原名（不动协议、不动引擎）

```
落盘名：  8f3c1e2b-4d7a-4f1e-9b2c-0a1b2c3d4e5f__季度经营分析.pptx
          └──── UUID（唯一性/防碰撞）────┘ └─ 清洗后的原名（可读性）─┘
```

- **宿主**（`routes.ts`）：新增 `safeFileLabel(name)` —— 取 basename、去掉路径分隔符与控制字符、替换 `\ / : * ? " < > |` 为 `_`、按 UTF-8 字节截到 60 字节（不截断多字节字符）、空则 `file`；落盘为 `${uuid}__${label}${ext}`。
- **清洗顺序保持**：`pruneAttachments` / `SAFE_EXTENSION` / `referencedAttachments` 全部按**整条路径**比对，只是文件名变长，逻辑零改动。TTL 与"被引用不删"策略不变。
- **客户端**（`DSchatPanel.tsx`）：上传成功后不再只存 path，而是存

  ```ts
  interface ComposerAttachment { path: string; name: string; mediaType: string; kind: 'image' | 'file' }
  ```

  - `name` = 宿主返回的 `name` 字段（本来就已经返回，此前被丢掉）；宿主未返回时回退到剥掉 `uuid__` 前缀的 basename。
  - `kind` = `mediaType.startsWith('image/')` —— **用于决定渲染缩略图还是文件 chip**。
  - 发送/排队/恢复仍只把 `path` 交给引擎（`engine.attachFiles(paths)`、`/send { images }` 均不变）。

- **历史消息里的附件**（旧数据只有路径）：新增 `displayNameOf(path)`，把 `uuid__` 前缀剥掉后再显示；旧的无前缀路径原样显示。**老会话因此自动受益**，无需迁移。

### 4.3 缩略图渲染

| 类型 | 渲染 | 尺寸 |
|---|---|---|
| 图片 | `<img>` 缩略图 + 右上角 `✕` 删除 | 56×56，圆角 8px，`object-fit: cover`，1px 边框 |
| 非图片 | 现有 chip 样式：📎 + 真名（省略号）+ `✕` | 高 26px，max-width 260px |

- 图片来源：**新增宿主只读路由** `GET /api/dsh-dschat/attachment?path=<abs>`，仅允许读 `<dataDir>/attachments/` 下的文件（`resolve` 后做前缀校验，杜绝目录穿越），`Content-Type` 由扩展名反查，`Cache-Control: private, max-age=300`，同时返回 `Content-Disposition: inline; filename*=UTF-8''<原名>`；返回 404 时前端退化成文件 chip（附件被 TTL 清理 / 数据目录迁移的场景）。
- 为什么不做 data URL：24MB 图片 × 10 张以 base64 常驻内存会明显拖慢面板，并且 `lib/client.js` 是单文件 bundle，不适合塞二进制。走宿主路由也让**恢复出来的老会话**同样能看到缩略图。
- 可访问性：`<img alt={name}>`；删除按钮 `aria-label` = 「移除附件 <name>」。

## 5. 思考内容：默认一律折叠（含流式过程中）

现状（`Markdown.tsx` → `Thinking`）：

- `useState(live)` 初始为 **live 就展开**；
- `useEffect` 里 `if (live) setOpen(true)` —— 流式期间持续强制展开；
- 结束后 `if (wasLive.current) setOpen(false)` 才折回去。

→ 用户体验就是「思考时铺开一大段，答完再收」，与需求相反。

### 改动（很小，但语义是新的）

```ts
const [open, setOpen] = useState(false)     // 永远默认折叠
// 删除「live 强制展开」的 effect
// 保留「live 结束后若有 wasLive 则 setOpen(false)」→ 可一并删除，改为：
//   用户手动展开后，流式结束不自动收起（尊重用户意图）
```

- 折叠态那**一行**同时承担「思考中」的可见性：`live` 时仍渲染 `ThinkingLive`（首行 + shimmer），文字如「思考中：…」，所以**信息不丢，只是不再铺开**。
- 点击该行仍可手动展开；展开后再点正文收起的行为不变。
- 自动滚动到底部的逻辑只在 `open` 时生效，折叠态不再触发。

## 9. 实现结果（v0.4.0）

评审通过的 5 个决定**全部按建议落地**，四项需求逐条对照如下。

### 9.1 需求 → 落地

| # | 需求 | 实现 | 证据 |
|---|---|---|---|
| 1 | 上传保留文件名 | 宿主落盘名 `uuid__原文件名.ext`（`fileLabel` 清洗 + 60 字节 UTF-8 安全截断），客户端 chip 用宿主回传的 `name`，不再 `basename(path)`；历史消息用 `displayNameOf()` 剥掉 `uuid__` 前缀 | `test/host-smoke.test.ts` 断言存储名形状与 `name` 回传；ui-shot 探针：`title="季度 经营 分析.png"`、`usesUuid:false` |
| 2 | 图片显示缩略图 | 56×56 `object-fit: cover` 缩略图（悬停/聚焦出现 ✕），非图片仍是文件 chip；图片来源是新增只读路由 `GET /api/dsh-dschat/attachment?path=` | ui-shot 探针：`className:"dsh-dschat-thumb"`、`thumbnailAskedFor` = 存储路径；`errors: []`（缩略图请求不产生控制台错误） |
| 3 | 思考默认折叠 | `Thinking` 初始 `open=false`，删掉「live 就展开」的 effect；折叠态那一行在推理期间渲染实时 `思考中：<最新内容>`；**读者自己点开的行**在思考结束时才自动合上 | `client-render.test.ts` 重写该用例：运行中 = 折叠 + live 行；展开面用新的 `defaultOpen` 测试缝驱动 |
| 4 | 按钮移到输入框上方 / 顶部只留品牌 + 状态灯 | header = 🐳 + `DeepSeek Chat` + 7px 状态灯；三个窗口按钮 + `⇄ DSH 迁移` 进 `.dsh-dschat-actions`（输入卡片之上、卡片之外）；`···` 菜单挂到状态灯上 | ui-shot 探针：`windowControlsInHeader:0`、`actionRowAboveCard:true`、`lampMenu` 三项 + 标题句；storefront 三张图已重渲染 |

### 9.2 与设计稿的偏差（都是实现时才看见的）

1. **状态灯需要和菜单共用同一个定位盒子**。设计稿把菜单面板和灯并列在 header 里，实现后发现
   菜单的包含块变成了「宽度为 0、且已被 flex spacer 推到最右」的兄弟节点：230px 面板在
   x=1266 弹出（灯在 x=148），直接出界。改成 `.dsh-dschat-lamp-wrap` **包住**灯 + 菜单。
   这是设计稿看不出、只有量出来才知道的一类错误，已写进 README。
2. **`attachment` 路由改为整读后 `res.end(bytes)`**，不是流式 `pipe`。文件本来就在 24 MiB 上限内，
   而流式会让这一族路由多出第二种响应形状（其余路由都是 `writeHead` + `end`）。
3. **缩略图 `<img>` 不做 `onError` 降级**（设计稿提到过）。附件被 TTL 清理时浏览器只显示空框，
   面板不会因此崩——但也不会把它换成文件 chip；这条留在「已知限制」。
4. **历史消息的图片 chip 多了一个 ↗ 打开链接**（非图片没有）。不改消息内联缩略图。

### 9.2b v0.4.1 修正：菜单落点、按钮形状、弹层方向

用户对 v0.4 落地结果提了三轮返工意见，逐条落地如下。这个菜单**一共搬了两次**，两次的
理由不同，值得记下来——它说明「放哪儿」有两个独立的判据，而 v0.4 和 v0.4.1 各只满足了一个：

| 位置 | 满足 | 不满足 |
|---|---|---|
| 状态灯（v0.4 原设计） | 语义同源：菜单描述引擎，灯报告引擎 | **可达性**：7px 的点读起来是读数不是按钮，「导出 markdown」没有可见入口 |
| 动作行行尾（v0.4.1 中间稿） | 可达性：读者会在那儿找控件 | **归属**：那一行是**这次对话**的动词，而这四项没一项关于这段对话 |
| **标题栏最右（最终）** | 两者都满足 | —— |

判据因此写成一句话：**标题栏放面板级的东西，动作行放对话级的东西**。

1. **`···` 在标题栏最右端**，菜单**向下开**。标题栏里两个弹层（它和状态灯）都由
   `.dsh-dschat-header .dsh-dschat-pop` 统一定向——**按「条」写、不按按钮写**，
   以后往这条栏里再加控件不会重犯。灯因此只剩「这句话什么意思」的答案（一整块面板里
   只有那一句状态话）。
2. **四颗按钮统一成宿主输入框的按钮样式**：`.dsh-dschat-tbtn`，28px 高、16px 图标、13px 文案、
   静止态透明 + `label-secondary`，强调色只留在 hover 和按下/打开态。§3 里「沿用现有
   `dsh-dschat-btn-primary` 视觉（蓝调）」这条设计说明随之作废——在「主要动作是一颗 16px
   强调色圆」的输入卡上方，填色 chip 会和发送键抢注意力。
3. **三颗对话按钮从图标方块改成「图标 + 文字」**（`新建对话` 那条要求，用户确认时扩到三颗）。
   §3 的「34px 方块 + 16px 图标」以及 `.dsh-dschat-hbtn` 这一族样式随之删除：
   方块里的一个图标是「你得先知道它是什么」的控件，而这一行是读者唯一会去找
   「新对话」「会话列表」的地方。文案用短名词（`会话列表`），`title`/`aria-label` 保留长句
   （`收起会话列表`）——**按钮是什么**和**按钮做什么**是两句话。
4. **弹层方向按所在的条决定**：动作行在底部 → 向上开；标题栏在顶部 → 向下开。
   这是设计稿 §3 完全没预见的一类错误（它只写了弹层内容，没写它朝哪儿长）：`top: 36px`
   的迁移面板向下铺过输入框和工具行，正好盖住它要操作的东西；而在标题栏沿用同一条规则，
   面板会落到 y=-35（窗口外）。
5. **锚点算术依赖包裹盒的尺寸**：包裹盒作为 flex item 会被拉成动作行高度（36px），
   `bottom: calc(100% + 8px)` 因此解成 36px 而不是 8px。`align-self: center` 是修复，
   守卫测试盯着它（详见 README「动作栏」一节）。

### 9.2c v0.4.2 修正：搜索按钮删掉（并修好它遮住的 bug）

用户提出「输入框上的搜索按钮感觉不是高频功能」（同时明确保留会话记录里的搜索），结论：**同意**。

**它只做两件事**：列表收起时把列表叫回来、把光标放进列表顶部的搜索框。而列表开着时（默认）
那个搜索框就在同一屏左侧几十像素处——按钮是一份更啰嗦的拷贝。它也确实不是一种**模式**：
`会话列表 / 新对话 / 迁移` 都会改变面板的状态，而「搜索这段对话」只是把光标放到一个已经在屏幕上的
输入框里。动作行因此从四颗变成三颗。

**但删它之前必须修一个潜伏的 bug**：`⌘K` 原本直接 `searchRef.current?.focus()`，列表收起时这个
ref 是 `null`（元素不在 DOM 里），于是**恰恰在快捷键最有价值的状态下，`⌘K` 静默失效**。
按钮当时是那条路径上唯一的入口——这就是它不能单独删掉的原因。改为走 `openSearch()`
（与按钮同一条路径：先展开列表，聚焦交给随后的 effect）之后：

| 场景 | 入口 |
|---|---|
| 列表开着（默认） | 顶部的搜索框，或 `⌘K` |
| 列表收起 | `⌘K`（修复后可用），或先点「会话列表」再点搜索框 |

**`⌘K` 的提示跟着功能走**：原来是按钮的 tooltip，现在挂在搜索框自己的 `title` 上
（`搜索会话内容（⌘K）`）。没人宣传的快捷键等于不存在，而这句话应该挂在它描述的那个框上。
失效的 `searchOpen`（那颗按钮的点亮态）与 `action.search` 文案键一并删除——
`.dsh-dschat-tbtn-on` 仍然是「按下/打开」的唯一表达，由 会话列表 与两个弹层触发器共用。
